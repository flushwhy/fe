01 / Quick start

From zero to project.

Install Fe using the instructions in the repository, then choose a template that fits your project. Templates are maintained separately so they can evolve independently of the CLI.

Fe orchestrates external tools. Install the compiler, engine, runtime, or distribution CLI required by the command you want to run.

1. Install Fe

Use the current installation instructions and release downloads in the source repository.

https://github.com/flushwhy/fe/releases

2. Explore templates

fe template list

List available remote templates before selecting one.

3. Create your project

fe init --template cpp-raylib-xmake --name my-game

Replace the template ID and project name with your preferred setup.

4. Read command help

fe --help

Commands and options can change between releases; local help reflects the version you installed.

02 / Command guide

Find the command you need.

fe init

Create a project from a language default or named template. Use fe template list to discover template IDs.

fe template list

List available remote templates.

fe template update <template-id>

Refresh a named template in the local cache.

fe build

Run the configured build targets from .fe.yaml; use --platform to select one target.

fe watch --ignore-dir <name>

Watch supported project files and exclude additional directory names from the watcher.

fe export --list-presets

List Godot export presets and expected output paths without exporting.

fe godot

Godot engine discovery, diagnostics, export, and native extension helpers.

fe o3de

O3DE project and engine registration and management helpers.

fe pack

Pack source sprites into one or more configured sprite sheets.

fe transcode

Transcode media with the configured codec and output settings.

fe release --dry-run

Preview configured build, export, packing, and publishing steps without running them.

fe release

Run the release workflow configured for your project; packing errors stop publication.

fe manifest

Write a JSON inventory of artifacts with platform, size, SHA-256, version, and commit metadata.

fe doctor

Check build target configuration and, for Godot projects, executable and export-preset prerequisites.

fe --help

Show the commands and flags available in your installed Fe version.

03 / Configuration

Your project, your settings.

Fe reads project configuration from .fe.yaml. Keep build commands, output folders, and publishing details alongside the project rather than hidden in a developer's shell history.

Browse examples on GitHub ↗
.fe.yaml · example
# Configure platform build commands
build:
  targets:
    - platform: linux-x64
      cmd: "gcc -o builds/linux-x64/game src/main.c"
    - platform: windows-x64
      cmd: "x86_64-w64-mingw32-gcc -o builds/windows-x64/game.exe src/main.c"

# Keep output paths and publishing settings
butler:
  directory: "builds"

itchio:
  username: ""
  game: ""

This is an illustrative snippet. Start from the config generated by your Fe version and adjust it to your project.
